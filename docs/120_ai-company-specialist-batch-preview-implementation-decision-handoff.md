## Decision Handling

Only an exact valid approval may be accepted as `DEC-176`. Any missing, widened, stale, or contradictory field leaves implementation blocked. An evidence request, rejection, or deferral records no runtime outcome. The future implementation must keep the preview separate from the schema-v20 durable concurrency and retry/recovery stages described in the plan.

## Acceptance Criteria

- The implementation follows every exact field, limit, normalization, digest payload, error status,
  success-envelope, redaction, and browser invalidation rule in `docs/119`.
- The preview uses one read-only state load and no `saveState`; focused smoke compares state bytes
  before and after success, exact replay, and every representative failure.
- The source gate rejects linked, closed, stale, cross-project, unbound, provider-backed, or
  already-compiled Council chains before path hashing or output.
- The fixed two-cell preview is deterministic and deeply frozen. Same current state and normalized
  request produce the same preview object; `evaluatedAt` changes identity.
- No response contains snapshot, derived state, transcript, provider evidence, source body,
  credential, environment value, or executable result.
- The runtime exposes no GET, start, cancel, retry, execute, persist, result-application, or
  WorkOrder mutation path for this preview.
